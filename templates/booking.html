Client traffic and attack scenarios

Local demo only. These controls act as the customer browser, sending real requests to this server. The dashboard only observes. Runs can reserve sample seats and raise alerts; restart the server to reset.

Customer browsing

Loads events and two seat maps, like a visitor comparing shows.

Booking rush

Eight buyers race for the same seat at once. Exactly one wins; the rest get SEAT_UNAVAILABLE. A rush can also trip the failure alert - that is expected.

Repeated booking failures

Three bookings for an event that does not exist, raising the HIGH repeated-failure alert.

Bot burst

Twelve rapid-fire booking attempts in one burst, raising the MEDIUM request-burst rule used to flag scalper-style automation.

Malformed input

Sends invalid JSON, wrong field types, missing fields, an oversized body and invalid objects. Each rejection has a WARN log and error trace. Three malformed requests raise the MEDIUM malformed-input alert.

Successful checkout

Reads available seats and confirms one. Follow validation, reservation and persistence.

Double-booking protection

Books a free seat, then tries it again. Watch the second request get a 409 conflict.

Multi-seat traffic

Four independent seats booked concurrently, like different customers checking out.

Invalid-seat probing

Three requests for seats outside the map. Watch inventory reject them and raise a failure signal.
